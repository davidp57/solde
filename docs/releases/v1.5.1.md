## Banque multi-comptes (BIZ-034)

- Chaque transaction bancaire est désormais associée à l'un des deux comptes : **Courant** (512100) ou **Épargne / Livret A** (512102).
- La vue Banque propose un **filtre par compte** (Tous / Courant / Épargne).
- Le solde du compte épargne est affiché dans une **stat card dédiée** sur le tableau de bord.
- L'import OFX supporte désormais les **fichiers multi-comptes** : les transactions sont automatiquement attribuées au bon compte via l'ACCTID configuré dans les réglages. Pour les fichiers mono-compte, la résolution est également automatique si les ACCTID sont configurés.
- Un **cut-off automatique** lors des imports OFX/QIF/CSV ignore les transactions antérieures au dernier import Excel du même compte, évitant les doublons lors du passage d'Excel à OFX.
- Les **virements internes** entre les deux comptes (512100 ↔ 512102) génèrent des écritures comptables cohérentes : seul le côté Courant produit des écritures.
- Nouvelle catégorie bancaire **« Sans écriture »** (`no_entry`) : une transaction avec cette catégorie ne génère aucune écriture lors du rapprochement.
- Deux nouveaux champs dans les **réglages association** : identifiants ACCTID OFX pour le compte courant et le compte épargne.
- **Migrations Alembic** :
  - `0050` — colonne `bank_account` sur `bank_transactions` + index
  - `0051` — colonnes `bank_account_courant_acctid` / `bank_account_epargne_acctid` dans `app_settings`

## Mode téléphone (BIZ-164)

- Les principales vues de liste s'affichent en **cartes empilées** sur les écrans ≤ 767 px : Factures client et fournisseur, Contacts, Banque, Dépôts, Règlements, Caisse, Salaires, Employés, Comptabilité, Exercices, Règles comptables, Journal, Balance, Bilan, Résultat, Utilisateurs.
- Les **dialogues** passent en pleine largeur (100 vw) sur mobile avec une hauteur max de 95 dvh.
- Les **cartes de synthèse** (stat cards) s'affichent sur 2 colonnes sur mobile.
- Les détails de coupures d'un dépôt espèces sont affichés directement sur chaque dépôt en attente du tableau de bord.
- À l'ouverture du formulaire de paiement chèque, le **numéro de chèque est suggéré automatiquement** au format `AAAAMMJJ.NN` (exemple : `20260504.01`). Le modèle est configurable dans les réglages (section Règlements, variable `{date}.{seq}`).
- **Migration Alembic `0049`** — colonne `cheque_number_template` dans `app_settings`.

## Corrections de bugs

- Le **format de date** dans le formulaire de saisie d'écriture manuelle (journal) utilisait l'affichage mm/dd/yyyy du navigateur au lieu de dd/mm/yyyy — corrigé avec `AppDateInput`.
- Le **compte 512102** (Livret épargne) n'était pas mis en valeur dans la vue Balance — ajout de la couleur orange dans les styles de focus.
- Les erreurs de validation (422) lors de l'import OFX/QIF/CSV étaient silencieuses côté backend et non affichées côté frontend — ajout de logs `warning` et d'un toast d'erreur avec le message de l'API.
- Le champ **« Compte cible »** dans le dialogue d'import s'affiche maintenant uniquement quand les ACCTID ne sont pas encore configurés.
- Le journal filtré sur un compte affichait des totaux erronés pour les écritures groupées (total de l'écriture complète au lieu de la contribution du compte filtré).
- Une écriture manuelle sans `fiscal_year_id` fourni par le frontend était invisible au filtre par exercice — le `fiscal_year_id` est maintenant dérivé automatiquement de la date de l'écriture.
