# Notes de release — v1.2.1

**Date** : 2 mai 2026
**Branche** : `develop` → `main`
**Type** : mineure (nouvelles fonctionnalités + correctifs, rétrocompatible)

---

## Résumé

Cette release couvre trois axes majeurs :

1. **Écritures comptables automatiques au rapprochement bancaire** — chaque rapprochement génère désormais les contreparties en partie double selon la catégorie de la transaction
2. **Lot I-BNK** — ergonomie bancaire : édition de catégorie, colonne rapprochement inline, boutons de rapprochement en masse
3. **Lot J** — wizard facture rapide et gestion des contacts : bouton e-mail dans la confirmation du wizard, marquage client indésirable, gestion de plusieurs adresses e-mail par contact
4. **Correctifs de prod** (TEC-152/153/154/146) — fuseau horaire Docker, isolation logs pytest, robustesse backup, aperçu PDF cross-browser

Toutes les modifications sont rétrocompatibles. La mise à jour nécessite un rebuild Docker (2 migrations Alembic appliquées automatiquement au démarrage : 0046 et 0047).

## Nouvelles fonctionnalités

### BIZ-141 — Écritures comptables automatiques au rapprochement bancaire

- Le rapprochement d'une transaction bancaire (bouton par ligne, « Tout rapprocher » ou « Rapprocher avant… ») génère désormais des écritures comptables automatiques selon la catégorie :
  - `BANK_FEE` → règle *Frais bancaires*
  - `SOCIAL_CHARGE` → règle *BANK_SOCIAL_CHARGES*
  - `GRANT` → règle *SUBSIDY_RECEIVED*
  - `INTERNAL_TRANSFER` → transfert épargne ↔ courant
- Source `bank_transaction` traçable dans le journal comptable avec libellé et référence bancaire

### Lot I-BNK — Ergonomie bancaire (BIZ-133/134/135)

- **Édition de catégorie** (BIZ-133) : icône crayon dans la colonne Catégorie pour modifier la valeur détectée, mise à jour via `PUT /api/bank/transactions/{id}`
- **Colonne Rapprochement inline** (BIZ-134) : tag vert « Rapproché » ou bouton « Rapprocher » cliquable directement dans la cellule — plus lisible et accessible
- **Rapprochement en masse** (BIZ-135) : boutons « Tout rapprocher » et « Rapprocher avant… » dans la barre d'outils du relevé ; nouvel endpoint `POST /api/bank/transactions/reconcile-bulk`

### Lot J — Wizard & contacts (BIZ-144/145/147/151)

- **Wizard** (BIZ-144) : la confirmation affiche le nom complet du contact (`{Prénom} NOM`)
- **Wizard → e-mail** (BIZ-145) : bouton « Envoyer par e-mail » directement dans la confirmation ; le wizard reste ouvert, le dialogue d'envoi s'ouvre par-dessus ; badge « E-mail envoyé » après envoi
- **Multi-emails** (BIZ-147) : jusqu'à 2 adresses e-mail supplémentaires par contact (libellé libre) ; table `contact_emails` (migration 0047) ; le dialogue d'envoi de facture liste tous les destinataires — un seul → champ lecture seule, plusieurs → cases à cocher pré-cochées
- **Client indésirable** (BIZ-151) : toggle `blocked` dans la fiche contact (types client/les_deux uniquement) ; badge rouge « Indésirable » dans la liste ; blocage strict côté backend (HTTP 422, `BlockedContactError`) et frontend (message d'erreur, bouton désactivé)

### BIZ-139 — Prévisualisation des factures fournisseur

- Dialogue de prévisualisation accessible depuis l'icône œil dans la liste — infos clés, historique des paiements, aperçu PDF/image intégré avec boutons télécharger et remplacer
- Navigation ‹ précédent / suivant › dans la liste filtrée courante
- Historique contact : prévisualisation inline (sans Dialog imbriqué), avec navigation entre factures du même contact
- Nouvel endpoint `GET /api/invoices/{id}/file`

## Correctifs

- **TEC-152** — Docker : `TZ: "Europe/Paris"` dans `docker-compose.yml` — horodatages des logs en heure locale
- **TEC-153** — Logs pytest : handler fichier désactivé sous pytest ; logs SQLAlchemy reclassés `INFO → DEBUG`
- **TEC-154** — Backup : suppression du fichier de destination en cas d'échec ; chemin absolu de la base source
- **TEC-146** — Aperçu PDF : `<object type="application/pdf">` remplace `<embed>` — fonctionne sur Chrome et Firefox
- Référence OFX (FITID) : jamais stockée dans `Payment.reference`, jamais affichée dans l'UI
- Factures fournisseur : statut initial `sent` (au lieu de `brouillon`) pour les factures créées manuellement
- Salaires : écritures comptables datées au dernier jour du mois (au lieu du 1er)
- Import OFX : détection et rejet explicite des fichiers multi-comptes
- Import bancaire : duplication silencieuse — résultat avec nb opérations créées vs ignorées
